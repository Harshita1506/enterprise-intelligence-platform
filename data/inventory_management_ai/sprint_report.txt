1. Sprint Executive Summary
Sprint 6 was a highly complex iteration focused on establishing our first machine learning baselines and connecting to external supplier APIs. The engineering team successfully completed the core Azure Data Factory pipelines and finalized the Vue.js frontend architecture. However, the data science deliverables were heavily impacted by the discovery of systemic data quality issues within Oracle NetSuite. Additionally, integration with our primary supplier, FastenCo, had to be completely redesigned from a REST API approach to a batch SFTP approach. As a result, several key machine learning and backend tickets have spilled over into Sprint 7.

5. Current Blockers & Issues

Dirty Historical Data (Critical): The machine learning models cannot accurately calculate supplier lead times because 35% of the legacy Oracle NetSuite data is missing receiving dates. The data science team is actively writing scripts to scrape warehouse logs to backfill this data, stalling all model training.

Supplier API Capabilities: FastenCo cannot support our required API polling frequency. The backend architecture had to be redesigned mid-sprint to accommodate a legacy batch file transfer system, resulting in lost engineering hours.

6. Technical Debt & Quality Notes

Data Imputation Debt: The scripts being written to backfill NetSuite data from warehouse logs are highly fragile and specific to this one-time migration. We are accepting this technical debt to unblock the ML team, but these scripts must not be merged into the master production pipeline.

Critical Bug SNT-255: The Azure Data Factory pipeline failed on day 12 of the sprint due to a transient network timeout with NetSuite, highlighting a lack of robust retry logic. Emily Davis has logged this for immediate remediation in Sprint 7.
